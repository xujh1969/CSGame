# Godot 4.x FPS Rig Diagnostics

This is a **read-only diagnostic script**, not a rigging or animation replacement.

## Setup
1. Copy `FPSRigDiagnostics.gd` into `res://debug/`.
2. Create an isolated test scene with your real arms GLB, rifle scene, a `Camera3D`, and their existing `Skeleton3D`/`AnimationPlayer`.
3. Add a plain `Node` named `RigDiagnostics`, attach the script, and assign the exported NodePaths in the Inspector.
4. Make `RightGripSocket` and `LeftGripSocket` as `Marker3D` nodes under the rifle, positioned *at the desired palm target*, not arbitrarily at the center of a handle.
5. Under the arm's `Skeleton3D`, create `BoneAttachment3D` nodes assigned to the actual right/left hand bone. Add `RightPalmMarker` / `LeftPalmMarker` as child `Marker3D` nodes, each tuned to the palm contact point and local orientation used by its matching gun socket.
6. Set `required_bones` to **actual imported bone names**; e.g. `hand.L` / `hand.R` or `mixamorig:LeftHand` / `mixamorig:RightHand`.
7. In-game, press **F9**. The script saves a JSON report and a PNG to `user://fps_rig_debug/`; it also prints absolute paths in the Godot Output panel. Send both files to Codex.

## How to use during Reload
- Right-hand contact remains expected while the rifle is held by the right hand.
- Left-hand contact to the **foregrip** is not expected while reaching toward / holding a magazine: temporarily set `expect_left_hand_gripping = false` on this diagnostic node, or use a separate contact check against a magazine marker in those keyframes.
- Make snapshots at the phases: Idle, Fire, Reload-start, magazine-grasp, magazine-insert, Reload-end, ADS.

## Important limitations
- This script detects *naming*, parent hierarchy, global/rest coordinates, negative determinant, socket contact distances/angles, current animation inventory, and one sight marker's on-screen position. It does **not** prove that a glove mesh is anatomically the left or right hand merely from the bone names. Confirm anatomical handedness visually with open fingers, or inspect model geometry/weights in Blender.
- The default 4 cm / 25° grip tolerances are only preliminary; adjust to your model's scale, marker definitions, and animation phase.
- Correct wrist-to-wrist / wrist-to-handle measurements are **not** valid grip tests: use calibrated *palm contact* and *weapon socket* markers as above.
- `get_bone_global_pose()` is relative to the Skeleton3D node, **not actual world space**. This script converts it via `skeleton.global_transform`.
- A valid rifle sight alignment and a well-composed Hip-fire camera are different tests. Only measure ADS sight centering in ADS mode and compare to a manually-approved screenshot reference in Hip-fire.
- If AnimationTree drives playback, treat it as the animation controller; don't concurrently call `AnimationPlayer.play()` for the same skeleton.
- If an IK / SkeletonModifier3D pipeline changes bone poses after an animation update, sample after the relevant modifier update to compare the *final* pose; this simple snapshot is mainly for baseline diagnostics.
- The code has been checked against published Godot 4.x APIs, but has **not been executed against your exact engine version/project**. It may need node-path or integration adjustments.

## Regression acceptance protocol
A. Idle: right hand on main grip, left hand on foregrip, rifle in the lower/right camera area and sight not occluding center.
B. ADS: sight marker projects near reticle center (camera position normalized to ~0.5,0.5); ensure weapon model actually points forward.
C. Fire: no detachment, recoil returns to same grip contacts.
D. Reload: right hand continues to hold grip; left hand leaves foregrip, grasps magazine, removes/inserts it in defined phases, then returns; no wrong-hand cross-attachment.
E. After modifying GLB/import/animation: rerun all above and compare saved JSON and screenshots to an approved baseline. Do not auto-accept a fix that makes another state worse.
