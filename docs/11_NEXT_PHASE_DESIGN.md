## 路线取舍

1. 推荐：先做多关卡最小骨架，用两个很小的灰盒证明切换与重开，再制作 20–30m 写实样板；样板通过后完成第一关，再扩展其他关卡。系统复用与视觉质量都有可评审结果。
2. 先大量做美术：容易尽早得到漂亮截图，但未证明关卡复用和加载，也可能返工资产尺寸和碰撞。
3. 直接制作三张完整大地图：产量和测试成本过高，视觉、动画与玩法问题不易定位，暂不采用。

整体定位保持 Windows 离线单人、虚构城市背景、线性推进；以手工设计核心路线和战斗点，seed 只提供安全装饰变化。

## 多关卡设计：先定三关，逐关生产

| 关卡暂名 | 空间主题 | 核心目标与差异 | 生产次序 |
|---|---|---|---|
| L01 旧城入口 | 主街、住宅、店面、破车与路障 | 到达街区入口；街角/高窗/掩体基础交战 | 现有 80m 升级，先完成这一关 |
| L02 市场穿行 | 窄巷、摊位、布棚、院落、小范围分支后汇合 | 抵达另一侧出口；较短视距、有限侧向威胁 | 第一关质量/性能成立后再做 |
| L03 工地撤离 | 较开阔路口、施工框架、围挡、车辆、固定高点 | 清除关键威胁并抵达撤离区；间歇推进与终局交战 | 复用前两关资产，增加施工套件 |

初期每关按约 5–10 分钟体验进行走测和调整，不按米数堆长度；这是设计意图，不是已测时长。三关总规模不作为一次性开发承诺。原 80m 场继续保留为回归测试关。

关卡内节奏：安全观察 → 敌情提示 → 小规模交战 → 换弹/整理 → 新空间或目标。目标先支持“清除指定遭遇 + 到达区域”；据此形成三关基础闭环，避免立即增加护送、复杂防守或收集系统。

## 多关卡技术边界

- LevelDefinition：每关唯一 id、标题、PackedScene 路径、配置路径、seed、所需遭遇、下一关 id。固定用明确 id 查找，不依赖数组顺序。
- LevelCatalog：登记可用关卡，启动前验证唯一 id、资源存在、下一关引用有效；最终关 next_id 为空。
- CampaignSession：记录当前关、已解锁关和场景切换状态；防止多次点击导致重复加载。只管理跨关状态，不持有敌人/碰撞节点引用。
- 每关仍有本地 GameFlow/EncounterManager，负责当前关胜负。胜利后显示“下一关 / 重玩”，最终关显示战役完成；失败只重试当前关。切换时清理旧关、音频、暂停状态与引用。
- 最初跨关重置 HP/弹药，不携带受伤/弹药，降低连续性和软锁风险。后续如需继承再单独设计。
- 建议最小本地进度只保存已解锁关与画质/音量；关内先支持“重试本关”。关内检查点是后续独立任务，不把世界节点整树序列化。
- 当前烘焙工具仍绑定这一段 80m，不能仅换 JSON 就声称支持任意关卡。需将关卡路径、核心约束和遭遇需求参数化，保留每关自己的布局/静态碰撞与导航，不发展成通用地图编辑器。
- LevelRuntime 的资源插槽保持表现与玩法分离。静态 GLB 接口不能直接用于完整骨骼敌人或第一人称武器，需要各自适配器和动画合同。

首个架构任务的验收必须覆盖 A→B、B 重试、从 A 重玩、最终关无下一关、重复切换无旧敌人/节点/声音残留、坏关卡配置明确失败，且原 80m 回归通过。加载画面先做简单反馈，不承诺无缝大世界。

## 敌人与第一人称资产

先做一个图5风格基础敌人，保留既有街角、窗口、掩体三职能；先靠姿态/站位/装备色差辨认，不同时做三套独立骨架。首批真实动作需要待机、行走、瞄准、射击、蹲伏、受击、死亡；敌方换弹/转移掩体在后续任务验证后增加。

用于建模的角色参考需全身 A-pose、双手张开、正/侧/背面、无遮挡；身体不携带融合在手臂上的枪，步枪独立模型绑定到手部挂点。图5持枪姿态用于外形目标，不直接作为唯一绑定参考。

图生 3D 只作为原始网格来源；必须另查拓扑、关节可变形性、骨架/权重、贴图、LOD 和实际 Godot 动作。不可将一个能显示的静态人物当作可战斗敌人。

第一人称武器与手臂独立制作：一支虚构步枪，独立弹匣、枪机和枪口挂点；手臂有手套/袖口。先完成持枪/ADS/射击/换弹动画，弹量逻辑继续由现有武器控制器决定，动画事件不能刷弹或重复开火。第三人称武器共用外形，但不用第一人称整套高精度网格。

首批只围绕 20–30m 样板：一套破损住宅立面、一套店面、路面/人行道材质、混凝土路障/木箱/沙袋、一辆废弃车、空调/电线/雨棚小套件、一个敌人基础角色、一套第一人称枪械手臂。先各完成少量可替换实例再增加变体。

每次给用户的制作单应包含：asset_id、用途/镜头距离、参考图提示词、独立部件清单、尺寸/原点/朝向、面数/贴图暂定预算、格式、来源/许可、接收验收标准。整条战斗街景图用于整体气氛，图生建模使用重新制作的单物件中性背景参考；不要求一次生成整条街。

当前不需要用户立即批量生成资产；先批准方案并确定首个样板镜头，再发第一批明确制作单。Blender 版本/连接在使用前实测，用户报告版本不当成已核验事实。

## 质量、性能与范围闸门

RTX2060 / 1080p Medium 60FPS 和 720p Low 30FPS 继续是设计目标，必须在目标硬件测量。样板阶段即查静态几何/材质批次、透明烟、阴影灯、纹理/显存，再决定每关密度；不同关卡资产按关加载卸载，不把整场战役留在内存。

不承诺单靠换模型达到参考图效果；光照、PBR/贴花、动作、音频、构图和优化都是独立工作。先固定少量可读交战，再讨论更多敌人、侧身探头、多武器或破坏系统。保持原有回归关可运行。
